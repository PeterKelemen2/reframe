# Test trim V2: validation (agreement, template, real-tool, engine, paths, in-place)

Branch `test-trim-V2`. I could not create `test-trim/V2` because the branch `test-trim` exists,
and git cannot have both `refs/heads/test-trim` and `refs/heads/test-trim/V2`. I used the
`test-trim-X` form that the other areas use.

Files (`packages/reframe/tests/validation/`): test_command_agreement, test_audio_agreement,
test_template, test_x26x_ffmpeg, test_options_ffmpeg, test_review_fixes, test_dryrun,
test_engine, test_levels_ffmpeg, test_paths, test_options_facade, test_ffmpeg, test_inplace,
test_inplace_fs, test_option_rules, test_hdr_ffmpeg.

## Numbers

| | Before | After |
|---|---|---|
| Tests | 503 | 476 (-27, -5.4 %) |
| Wall time (pytest, with `--cov --cov-branch`) | 49.5 s / 58.4 s | 45.4 s / 30.8 s |

The machine was shared with other agents, so the times are noisy (two runs each). Most of the
saving is the 24 audio agreement cases, at about 0.1 s each, so expect roughly 3 s less.

The area is already lean, so I removed little. Most of the tests are in three contract
matrices:

- the `PlanError` refusals (each one is needed by `test_every_plan_error_is_covered`);
- the snapshot jobs (each snapshot is a separate job);
- composite x26x parts × every speed preset (`option_default` reads per-preset tables, so
  each preset is a separate data point).

Also, 9 of the 16 files run the real FFmpeg.

## Deleted tests

### Subsumed by other tests in the area
- `test_inplace.py::test_source_writable`: `source_writable` with a view that says no, and with
  an object that is not a `WritableFiles` (gives yes). `test_inplace_fs.py::test_source_writable_asks_the_view_with_windows_paths`
  tests both. `LocalFileSystem.writable_file` (present / missing file) is tested directly in
  `test_inplace_fs.py::test_local_writable_file`. I also removed the imports that became
  unused (`PurePath`, `LocalFileSystem`, `source_writable`).

### Exact duplicate elsewhere
- `test_review_fixes.py::test_no_output_folder_points_at_a_job_field`: commit 6c298ca added
  this test and, in the same commit, changed the path of the `test_rules.py` case "fixed
  folder not chosen" to `output.path`. The test changes the same settings and asserts the
  same code at the same path. The rule case also has a negative test and checks the fix.
  Mutation M1 confirms this.

### Library behaviour only
- `test_template.py::test_demo_item_4_issue_json`: it dumps the issues with pydantic's
  `TypeAdapter`, prints them "for the step report" and checks that capsys captured the print.
  The only check on our code is the issue code, and
  `test_demo_item_4_unavailable_nvenc_names_the_closest_encoder` already asserts it, together
  with the message, the fix label, the patch and the revalidation.

### Cartesian product of independent factors (collapsed)
- `test_audio_agreement.py::test_codec_rules_builder_and_validation_agree`: 102 → 78 cases.
  - The "no source rate" variant now runs only for `stereo` and `unknown` (× 6 encoders). It
    used to run for all six basic layouts.
  - The source sample rate is used only by `snap_samplerate` (C-7 `planned_audio`, C-8 notes,
    C-12 `_samplerate`). None of these depend on the channel layout.
  - Every layout, the 5 libopus-refused layouts included, still runs with the known rate
    (44.1 kHz, which Opus lacks).
  - Removed: `{mono,5.1,5.1(side),7.1}-no-rate-{aac,ac3,eac3,libopus,flac,libmp3lame}`.
  - I updated the module docstring (17 → 13 sources, 9180 → 7020 tracks).

## Mutation checks

The script applies each mutation, runs the remaining tests, then reverts with
`git checkout -- <file>`. `git status` showed no change to production code after each one.

| # | Mutation | Remaining tests run | Result |
|---|---|---|---|
| M1 | `validation/naming.py` `_job_path`: `"path": "output.path"` → `"naming.output_folder"` | test_rules, test_review_fixes, test_engine | `test_rules.py::test_positive[fixed folder not chosen]` FAILED |
| M2 | `validation/inplace.py` `source_writable`: the final `return True` → `return False` (a view that cannot tell) | test_inplace, test_inplace_fs | `test_inplace.py::test_a_clean_in_place_edit_has_no_issues` FAILED |
| M3 | `validation/inplace.py` `source_writable`: `return fs.writable_file(path)` → `return True` | test_inplace, test_inplace_fs | `test_inplace_fs.py::test_source_writable_asks_the_view_with_windows_paths` FAILED |
| M4 | `batch/audio_rules.py`: `source_rate = ctx.stream.sample_rate` → `... or 44100` (no-rate handling of C-12) | test_audio_agreement (trimmed) | `[stereo-no-rate-libopus]` FAILED |
| M5 | `command/audio.py` `planned_audio`: `snap_samplerate(track.samplerate, stream.sample_rate or 48000)` | test_audio_agreement (trimmed) | `[stereo-no-rate-aac]` FAILED |
| M6 | `batch/audio_rules.py`: `wanted = ... else (source_rate or 48000)` (changes only C-12's note text) | test_audio_agreement (trimmed), then the original untrimmed file | Both pass: the original 102 cases miss it too, so the trim loses nothing here |

`test_demo_item_4_issue_json` had no meaningful mutation: it checks pydantic serialisation,
and the kept demo test asserts the code it checked.

Known trade-off of the audio trim: a bug that only happens when the source rate is unknown
*and* the source has more than 2 channels would now go undetected. Such a bug would have to
read the layout in the sample-rate path, and no code does that today.

## Uncertain, kept

- `test_inplace_fs.py::test_read_only_source_through_the_view`: the same as the positive case
  `inplace_read_only_source` in `cases_inplace.py` (which runs in `test_rules.py`, not my
  file). I deleted it, but the gate (my files only) then lost `validation/inplace.py:100`, so
  I restored it. You can delete it if the gate is judged across the whole directory.
- `test_audio_agreement.py`: you could drop more of the no-rate variant (keep only `unknown`),
  but I kept two layouts per encoder.
- `test_command_agreement.py::test_composite_parts_have_defaults` (66 cases): kept. The
  defaults are per speed preset (`option_default(sibling, preset_name)`), so each preset is a
  separate check of the shipped data, and `UNREACHABLE` in the same file depends on it.
- `test_command_agreement.py::test_snapshot_jobs_are_imported`: a trivial count guard, kept
  because it stops the 73 snapshot cases from passing on an empty import.
- `test_engine.py::test_job_rule_decorator_registers`: cheap. The meta-tests in
  `test_rules.py` read `rule.codes`, and an empty `codes` would make them pass without
  checking anything.
- `test_options_facade.py::test_search_psy_finds_psy_rd_and_psy_rdoq`: it overlaps
  `definitions/test_options_search_hdr.py`, but it goes through the facade (`app.jobs`) and it
  is the M9 demo item.
- All `*_ffmpeg.py` tests (real tool behaviour), all other `test_review_fixes.py` tests (bug
  regressions), and the template positive / negative tests ("Done when" of C-8).
