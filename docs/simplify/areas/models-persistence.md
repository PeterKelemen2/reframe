## Summary

The models themselves are lean: 24 files, almost no validators, no model that says the same thing as another one in a way that is cheap to merge. The complexity is in the two stores. `SettingsStore` and `PresetStore` (and `PresetStore._load` and `_incoming` against each other) repeat the same load pipeline four times: migrate, validate, sort the failure into "newer", "damaged" or "too deep", and report it. They also repeat the problem list and the protect/warn helpers. Around them sit things that only tests use: a `registry=` argument on both stores, `PresetStore.rename`/`duplicate`, `SettingsStore.save`, `EVENT_ADAPTER`/`EVENT_TYPES`, and a second copy of the Windows `PermissionError` retry that `queue/files.py` also has. Two persisted fields have no reader (`output.default_container`, `source.fingerprint.probe_hash`). Two items are decision-level: the `media_source` migration that no reader calls (0081), and the per-preset nesting limit (0015). Nothing here touches the atomic write, the backup, the newer-file protection or the unknown-field round trip.

  ```python
  def parse_document[T](kind: str, data: dict[str, Any], build: Callable[[dict[str, Any]], T],
                        registry: MigrationRegistry | None = None) -> T | UnsupportedSchemaVersion | str:
      """``build`` of the migrated data; the error of a document of a newer Reframe; or why it is damaged."""
      try:
          return build(migrate_document(kind, data, registry))
      except UnsupportedSchemaVersion as exc:
          return exc if is_newer(exc) else str(exc)
      except ValidationError as exc:

          return f"migration failed: {exc}"
  ```
